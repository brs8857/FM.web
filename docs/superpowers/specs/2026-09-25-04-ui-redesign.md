## 1. Goals

1. Make the era-draft idea visible on every screen (02 G14, 03 §4).
2. Turn each draft pick into a real decision with a visible constraint (02 G1, G2, G9, G10).
3. Cut the tactics screen to the levers that matter, with everything explained on tap (02 G3, G4).
4. Give the career a record and the player a way back (02 G6 UI side, G7, G11).
5. Mobile-first, native-feeling on iOS, first-class on desktop, and accessible (02 G12; roadmap Phase 1B goals).
6. Own identity: nothing that reads as Football Manager, Ultimate Team or Retro Bowl (03 §3).

## 2. Non-goals

- Engine or balance changes. The three club-season draw and redraws (§5.2) are reducer-level and are the only rule changes; they're listed as owner decisions.
- Match-day interactivity (Phase 3). §5.6 leaves a place for it.
- Accounts, purchases, telemetry (05, 06).
- A design-system-as-product. Tokens and primitives are for this app.

## 3. Visual identity

### 3.1 Concept

The game is about **33 years of football history** and **the manager's
board**. Those are the two surfaces:

- **The back page.** Information lives on newsprint: team sheets, league tables, the draft's club-season "cuttings", the record book. Typography does the work; there are no cards, gems or badges.
- **The chalkboard.** The pitch and everything tactical is chalk on slate: markers, lines, arrows. Dragging a player leaves a chalk trail; the identity the engine detects is written on the board in the manager's hand (typographically, not as a handwriting font).

The season plays out on a **vidiprinter**: a monospaced teleprinter feed
of results, which is both the visual signature (01 L4) and a faithful
reference to how the scores arrived in the era the game covers.

What this is not: not pixel-retro (New Star's), not glossy cards (EA),
not tiles (FM26), not the current dark-emerald "sports app" look.

### 3.2 Colour tokens

Defined as CSS custom properties on `:root`, redefined under
`[data-theme="dark"]` and under `prefers-color-scheme: dark` when no
explicit theme is set. Semantic names only; no raw hex in components. A
CI script (`scripts/check-contrast.mjs`) asserts every text/background
pair listed here meets WCAG AA 4.5:1 (3:1 for large text and UI borders).

| Token | Light "Newsprint" | Dark "Floodlit" | Use |
|---|---|---|---|
| `--paper` | `#F4EFE4` | `#15181C` | page background |
| `--paper-2` | `#EBE4D5` | `#1E2227` | panels, table stripes |
| `--rule` | `#C9C1B1` | `#3A3F46` | hairlines, dividers |
| `--ink` | `#1A1A1A` | `#ECE7DA` | primary text |
| `--ink-2` | `#5C5749` | `#A9A395` | secondary text (≥ 6:1 on paper) |
| `--signal` | `#E8A33D` | `#E8A33D` | the one attention colour: live ticker, the active draft slot, focus rings. **Never as text on light paper** (fails AA); ink-on-signal or signal-on-dark only |
| `--slate` | `#1E3D2F` | `#17302A` | chalkboard/pitch surface |
| `--chalk` | `#F7F3EA` | `#F7F3EA` | pitch lines, markers |
| `--win` | `#256B44` | `#6FCF97` | W results, promotion |
| `--draw` | `#6B6B6B` | `#9AA0A6` | D results |
| `--loss` | `#B0413E` | `#E07A74` | L results, relegation |
| `--action` | `#1A1A1A` | `#ECE7DA` | primary button fill (ink); label uses `--paper` |

Rationale: the only saturated colour is the vidiprinter amber, so it
carries meaning (something is live or needs you). Wins and losses use
muted pitch-green and brick that don't read as any club's kit. Buttons
are ink on paper, like a printed coupon, not a green pill.

### 3.3 Type

Two families, both SIL Open Font License, bundled in the app (no runtime
font fetch; the app must work offline and the App Store build has no
network dependency):

- **Barlow Condensed** (600/800) for headlines, the pitch marker labels, and big numbers — the back-page voice.
- **Barlow** (400/600) for body and controls.
- **IBM Plex Mono** (400/600) for the vidiprinter, seed codes, and league-table numerals (tabular figures).

Scale (rem, root 16 px; `html { font-size: 100% }` so iOS text-size
settings scale the app): 0.8125 / 0.875 / 1 / 1.125 / 1.5 / 2.25 / 3.5.
Line length capped at 60ch on wide screens. Sentence case everywhere;
uppercase only for the vidiprinter and slot codes (GK, CB…). No
letter-spaced uppercase micro-labels.

### 3.4 Shape, depth, motion

- Corners 4 px on paper elements (a printed slip), 999 px on chips; nothing else rounded.
- No drop shadows on paper. Sheets get a 1 px `--rule` top edge and a drag handle.
- Motion vocabulary: **slip** (a panel slides up 8 px and fades in, 160 ms), **type** (ticker text appears character-block by character-block, 20 ms per block), **stamp** (a revealed number scales from 1.15 to 1 over 120 ms with a 30 ms hold). Under `prefers-reduced-motion: reduce` all three become instant and the vidiprinter shows the full season with a "Show all" control.
- Haptics (native only, via Capacitor Haptics, no-op on web): light tap on pick, medium on draw landing, success notification on the final verdict.

### 3.5 Mark and icon

A condensed **XI** with a single chalk underline. App icon: chalk XI on
`--slate`. Favicon and PWA icons from the same SVG. No ball, no pitch
outline, no crest shape (crests are what clubs sue over, 03 §5).

## 4. Information architecture

### 4.1 Two modes

**Set-up** (no complete XI yet): a linear flow with a back button.
**Club** (XI complete): a persistent tab bar. Phones show it at the bottom
(iOS pattern, 49 pt plus the home-indicator inset); desktop and iPad
landscape show it as a left rail.

```
Home ── New career ── Era ── Formation ── Draft (full-screen flow, 11 picks, pausable)
                                              │
                                              ▼ XI complete
                    ┌───────────┬───────────┬───────────┬──────────┐
                    │  Squad    │  Board    │  Season   │  Club    │   ← tab bar
                    └───────────┴───────────┴───────────┴──────────┘
Season tab states:  Pre-season → Team sheet (reveal) → Vidiprinter → Back page → Window → next Pre-season
```

Mapping to `state.phase`: `formation` → Set-up; `draft` → Draft flow;
`tactics` → Club with Season tab in *Pre-season*; `reveal`/`result` →
Season tab; `transfer` → Season tab in *Window*. The tab bar is UI state
(`src/app/nav.js`), never saved. The player can look at any tab at any
time; only the Season tab's primary action advances the phase.

### 4.2 The "next action" rule (01 S2, 02 G11)

Every Club screen shows one **Next** pill in the top bar naming the single
action that moves the career on: "Set your tactic", "Kick off season 3",
"Close the window". The Home screen's resume card shows the same string.
`selectNextAction(state)` in `src/state/selectors.js` computes it.

### 4.3 Navigation on the web and desktop

Same structure. Desktop widths get two columns inside each tab (pitch or
list left, detail right) and keyboard shortcuts (§8). The browser back
button maps to the set-up flow's back and, in Club mode, to the previous
tab.

## 5. Screens

### 5.1 Home

- Resume card: "Season 3 · 2028-29 — **Kick off** when you're ready" with the club name, the current tactic's identity chip and cohesion label. One primary button (the next action), one secondary ("Club").
- New career.
- (Later, 06 §4) Today's draw.
- Bottom: settings and about links.

### 5.2 Draft

The screen that has to change most. Reads as a desk with cuttings on it.

**Layout (phone).** Top: a compact chalkboard (≤ 38 vh) showing the 11
slots; filled slots show a chalk surname, the active slot pulses in
`--signal`. Under it, a one-line **squad strip**: "4 picked · 3 from the
'90s, 1 from the 2010s · Cohesion: Rough". Then the **draw**.

**The draw (replaces the wheel; owner decision U1).** Tapping **Draw**
runs the ticker: club-season labels type past and settle on **three
cuttings** — three club-seasons drawn from the era range (three
`rng.pick`s, deduplicated). Each cutting is a newsprint header ("Leeds
United 2000-01") with the count of eligible players for this slot ("2
centre-backs"). Tapping a cutting opens its **team sheet**: the eligible
players as rows — surname, first name, age, nationality, natural side —
**in shirt order (by position code then age), never by rating** (02 G2).
Tapping a row shows a confirm sheet with the pick's effect on the squad
strip ("Era spread grows to 11 years: cohesion −2"; "Right-footed in a
left slot: −2") and a **Pick** button.

**Redraw (owner decision U2).** Two redraws per draft, shown as two chalk
ticks that get rubbed out. A redraw discards all three cuttings and draws
again. That is the R4 "skip at a cost".

**Why three.** Median pool sizes are 2–4 per club-season (02 G1);
three cuttings give roughly 6–12 options per pick and add a memory-test
layer ("which of these three squads had a great left-back?"), which is
the game's actual hook. Ratings stay hidden and unsorted, so this doesn't
make best-picking easier; it makes *knowing football* matter.

**Pause.** The draft autosaves after every pick (already true) and the top
bar has "Pause" which returns Home; Home then says "Draft in progress: pick
5 of 11".

**Relaxed pool** (bug #3) is shown as a cutting subtitle: "No wingers in
this squad — showing everyone", and off-position rows are marked.

**When the XI is complete**, the bench is added as today and the flow ends
on a **team-sheet slip**: the eleven surnames in formation order, the
squad strip totals, and "Go to the board".

### 5.3 Squad tab

Chalkboard on top (pinned at ≤ 42 vh on phones; left column on wide
screens), **team sheet** below: eleven rows plus the bench, each row shows
position code, name, age, nationality, and the current job/brief. Tapping
a row opens the **player sheet** (bottom sheet): identity line, the six
stats as **five-band pips without numbers** (the hidden-ratings rule,
owner decision U3, closing 02 G13: OV hidden until kick-off, stats shown
only as bands so the OV cannot be back-computed), job, brief, the two
personal dials, and "Swap with…". Bench rows can be dragged onto the board
or swapped from the sheet.

### 5.4 Board tab (tactics)

Same pinned chalkboard, draggable. Below it, in this order:

1. **Identity line** (always visible): the detected identity chip ("Gegenpress", "Low block counter", "No clear plan", or "Bespoke") and the **Cohesion meter** (renamed from familiarity, 03 §3.2) with its label. This is the engine's `synergyLabel` and `familiarity` surfaced as the first thing, so the player sees the consequence of G4 *before* touching anything.
2. **Style row**: horizontally scrolling chips for the seven presets. "Balanced" is relabelled **"Blank slate"** with the subtitle "no identity bonus" (02 G4). Selecting a preset rewrites the dials with a slip animation on each changed dial so the player sees what moved.
3. **Approach**: the three dials that matter most — Mentality (five labels, 03 §3.2), Tempo, Directness — visible by default.
4. **In possession** and **Out of possession**: collapsed disclosure groups holding the remaining eight dials and three toggles. Each group header shows a one-line summary of its current values.
5. **Strengths**: six horizontal bars (Attack, Creativity, Build-up, Press, Defence, Physical) replacing the radar; each bar shows the opponents' average as a tick mark so the number has a reference. Below, the readout notes as before, max three.
6. Sticky bar: **Kick off** (goes to the Season tab and dispatches `SIMULATE`).

**Dial** control: a slider with the value label, `−`/`+` step buttons (5 units) for one-tap adjustment and keyboard access, and an ⓘ that opens the term sheet. Tooltips on hover are gone.

**Term sheets** (01 O2): every game term is a `<Term>` that opens a
definition sheet on tap; definitions can contain further `<Term>`s.
Content lives in `src/content/terms.json`; the definitions are the
current tooltip and `desc` strings, rewritten to the new vocabulary.

### 5.5 Season tab

Four states, one screen:

- **Pre-season**: the season header, the opponents list with the promoted clubs marked, the current identity and cohesion, and **Kick off**. If the tactic hasn't been reviewed since the window closed, the Next pill says "Set your tactic" and links to the Board.
- **Team sheet (reveal)**: the existing staggered reveal, restyled: eleven rows print in, each rating **stamps** in, then the squad average. The one moment where an overall number is shown large. Keep 240 ms cadence; instant under reduced motion or when resuming.
- **Vidiprinter**: the 38 results type in on the teleprinter, newest at the bottom, with a sticky **league position ticker** at the top ("Week 12 · 4th · 24 pts"). Controls: **Pause**, **Skip to end**. After week 19 the feed pauses on a **half-season slip** (record so far, position) with "Continue" — a stopping point now (01 S1) and the place Phase 3 will add a mid-season decision.
- **Back page**: the verdict as a headline ("CHAMPIONS", "SAFE ON THE LAST DAY", "RELEGATED"), a standfirst (today's tier `sub`), the record line, the final table (collapsed under the fold, open by default on wide screens), the match list (collapsed), the strengths bars, and **Share** (§7). Then either **Open the window** or, after the final season, **Career complete** → record (§5.7).
- **Window**: the five candidates as cuttings (same team-sheet row style as the draft) with **Sign to bench** / **Replace…**; *Replace* highlights eligible slots on the pinned chalkboard instead of listing surnames (02 G11). League changes (relegated/promoted) as a short newsprint notice. **Close the window** → next Pre-season.

### 5.6 Room for Phase 3

The vidiprinter's half-season pause, the Pause control, and the per-week
row layout are designed so that match-by-match events (goals, cards) can
be added as expandable rows, and a tactical change can be offered at the
pause, without changing the screen's structure.

### 5.7 Club tab

- **Record**: every completed season as a row (season, finish, points, identity used, tier), best finish, titles, unbeaten runs. Needs `seasonHistory` (§9). Career complete shows the full record as a printable slip.
- **Career code**: the `careerSeed` as a 6-group code with Copy and "Start a career from a code" (01 P1; 06 §4 builds dailies on it).
- **Saves**: export, import, and (native) iCloud status (05 §5).
- **Settings**: theme (system/light/dark), reduce motion (follows system by default), haptics, club names (real/edited, 03 §5), text size note.
- **About**: version, privacy policy, licences, restore purchases (05).

### 5.8 First run (01 O1)

No tutorial. Three slips on first launch, one sentence each with the
concept's own visual (a cutting, a chalk marker, the ticker), then
straight into New career. Each Club tab shows a dismissable **coach's
note** callout the first time it is opened. `prefs.seenNotes` holds which
have been dismissed (per device, `fmweb.prefs`).

## 6. Responsive layout

| Width | Layout |
|---|---|

| 600–1023 px (tablet portrait, small laptops) | Two columns: chalkboard left (fixed 360 px), content right; tab bar bottom |
| ≥ 1024 px | Left rail tabs (72 px), chalkboard column (≤ 440 px), content column (≤ 60ch), optional third column for Strengths on the Board |

No horizontal scroll at any width from 320 px; `env(safe-area-inset-*)`
applied to the top bar, tab bar and sticky bar. Landscape phones collapse
the chalkboard to a strip with a "Show board" toggle.

## 7. Sharing (02 G8)

The back page has **Share**: renders the verdict slip to a PNG (canvas
from the same DOM measurements, 1080×1350) and calls `navigator.share`
with the image and a text line including the career code; falls back to a
download plus copy-to-clipboard. Native uses the same Web Share API in
WKWebView (Capacitor supports it) or the Share plugin.

## 8. Accessibility and native-feel requirements

Carried from Phase 1 spec §5.3, restated as acceptance criteria:

1. Viewport allows zoom (`width=device-width, initial-scale=1`); no `user-scalable=no`.
2. Every interactive element ≥ 44×44 pt; chalk markers get an invisible 44 pt hit area.
3. **Keyboard**: Tab to a marker, Enter selects, arrows nudge 2 units (Shift: 6) through `MOVE_PLAYER`, Enter on another marker swaps, Esc cancels, E opens the sheet. Desktop shortcuts: 1–4 tabs, K kick off/continue, D draw.
4. **Tap vs drag**: 8 px threshold; drops handled once (existing guard).
5. **Screen readers**: every marker `aria-label="Centre-back, Tony Adams. Press Enter to select."`; an `aria-live="polite"` region announces moves, swaps, draws and results; the vidiprinter announces the week's result only when paused or at the half-season slip, not per tick.
6. **Contrast**: all token pairs AA; checked in CI.
7. **Reduced motion**: §3.4.
8. **Text size**: rem-based scale; layouts tested at 200% browser zoom and iOS "Larger Text" via WKWebView (`-apple-system-body` sizing on `html`).
9. **Focus**: visible `--signal` focus ring, 2 px, offset 2 px, on every control.
10. **Native feel**: safe areas; bottom tab bar; sheets with drag handle, swipe-to-dismiss and focus trap; no hover-only affordances; `touch-action: none` only on the board; `overscroll-behavior: none` on the shell; `-webkit-tap-highlight-color: transparent`; system share sheet; status bar and splash colours from tokens; iPad two-column; haptics as §3.4.
11. axe: zero serious/critical violations on every screen in all three Playwright projects.

## 10. Component plan

New tree; `src/components/**` is deleted at the end of the release (see
plan). `src/ui` holds primitives, `src/pitch` the board, `src/screens`
the screens, `src/app` the shell.

```
src/
  styles/
    tokens.css        colour, type, spacing, motion tokens; light/dark
    base.css          reset, fonts (@font-face, bundled woff2), focus, reduced-motion
  content/
    terms.json        term → definition (markdown-lite, may reference other terms)
    notes.json        coach's notes per screen
    labels.js         vocabulary map (role/brief/mentality/cohesion labels)
  ui/
    Button, IconButton, Chip, ChipRow, Segmented, Toggle, Dial,
    Disclosure, Sheet, TabBar, TopBar, NextPill, Term, Callout, Toast,
    Meter (cohesion), StrengthBars, Stamp, Ticker, Cutting, TeamSheetRow,
    Slip, Table, LiveRegion
  pitch/
    Chalkboard, Marker, BenchRail, PitchLines,
    usePitchDrag (kept, moved), usePitchKeyboard (new)
  screens/
    Home, NewCareer/{Era, Formation}, Draft/{Draw, CuttingSheet, ConfirmPick, TeamSheetSlip},
    Squad/{SquadTab, PlayerSheet}, Board/{BoardTab, StyleRow, Approach, InstructionGroups, Strengths},
    Season/{SeasonTab, Preseason, TeamSheetReveal, Vidiprinter, BackPage, Window},
    Club/{ClubTab, Record, CareerCode, Saves, Settings, About}
  app/
    Shell (top bar + tab bar + sticky bar slots), nav.js (UI nav state),
    FirstRun, ErrorBoundary (kept), DatasetGate (kept), SaveMenu → folded into Club/Saves
```

**Styling approach (owner decision U4).** CSS Modules (built into Vite)
plus the token sheet. Tailwind is removed at the end of the release
along with the old components. Reasons: the design is token-driven and
small; utility classes were the mechanism by which the generic look
crept in; removing the dependency and its config is one less thing in
the native build. If the owner prefers to keep Tailwind, the same tokens
map into `tailwind.config.js` and the component plan is unchanged.

**Testing.** Each primitive gets a React Testing Library test for
keyboard and ARIA behaviour; each screen a render test against a fixture
state; Playwright covers the career smoke test on three projects, axe on
every screen, the phone checks (no horizontal scroll, sticky bar visible,
Draw button in view at every pick), and a visual snapshot per screen per
theme at 375 px and 1280 px.

## 11. Copy rules

- British English, sentence case, short. No exclamation marks.
- Never "Football Manager", "FM", "Premier League", or UEFA competition names in product copy (03 §3.1).
- Terms come from `content/labels.js`; screens never hard-code a role, brief or identity label.
- Numbers: tabular figures; points and positions in mono.
